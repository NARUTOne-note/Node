# S3 对象存储

> AWS Simple Storage Service，2006 年推出，是**对象存储事实上的协议标准**。
> 一句话：用 HTTP API 把海量非结构化数据（图片、视频、备份、日志、数据湖文件）以「桶 + 对象」的形式存起来的服务，容量近乎无限、按量付费。
>
> 相关：[oss.md](../servers/others-explain/oss.md)（对象存储通识）、[bucket.md](../servers/others-explain/bucket.md)（存储桶）、[minio-juicefs-s3.md](../servers/others-explain/minio-juicefs-s3.md)（JuiceFS S3 网关）、[database.md](./database.md)（存储层选型）

## 一、什么是 S3

- 全称 **Amazon Simple Storage Service**，AWS 的对象存储服务，对外只提供一套 **HTTP RESTful API**。
- 名词上的 S3 有两层含义：
  1. **AWS S3**：亚马逊云的具体产品；
  2. **S3 协议 / S3 兼容**：因为 AWS 的统治地位，各家对象存储（MinIO、阿里云 OSS、腾讯云 COS、Cloudflare R2…）都实现了同一套接口，代码换个 endpoint 就能跑。所以「上 S3」通常指**上 S3 生态**，而不是特指亚马逊。
- 定位上它不是一个「数据库」，但它是现代架构里最基础的**存储层**：存算分离的底座、数据湖的存储层、静态资源的仓库。

## 二、块存储 / 文件存储 / 对象存储

| 类型 | 数据组织 | 接口 | 容量 | 典型代表 | 适合存什么 |
| --- | --- | --- | --- | --- | --- |
| **块存储** | 裸磁盘块 | 挂载后自行格式化（ext4/xfs） | 有限（受磁盘/云盘规格限制） | 云硬盘 EBS/云盘、本地 SSD | 数据库数据文件、需要随机读写与低延迟的场景 |
| **文件存储** | 目录树 | POSIX（open/read/write/rename） | 有限到较大 | NFS、NAS、HDFS、FastDFS | 共享目录、中小文件、需要 POSIX 语义的场景 |
| **对象存储** | 扁平的 key-value | HTTP REST API（PUT/GET/DELETE） | 近乎无限，自动扩容 | **S3**、OSS、COS、MinIO | 图片视频、备份归档、日志、数据湖文件 |

**关键区别（也是最大的坑）**：对象存储**没有目录**。所谓 `img/a.png` 只是 Key 字符串里带了个 `/`，控制台按前缀模拟出目录树给你看，底层是扁平的。同理没有 rename、没有文件锁、不能只改对象的一部分——只能整体覆盖。

## 三、核心概念

| 概念 | 说明 |
| --- | --- |
| **Bucket（存储桶）** | 对象的容器，一切操作都发生在某个桶里。AWS 上桶名**全局唯一**（3~63 字符，小写字母数字和 `-`），因为桶名会进域名 |
| **Object（对象）** | 存储的基本单元，由 **Key + Data + Metadata** 三部分组成 |
| **Key（键）** | 对象在桶内唯一的完整路径字符串，最长 1024 字节，如 `img/2026/09/a.png`（`/` 无特殊含义） |
| **Region（地域）** | 数据所在的物理数据中心，如 `ap-southeast-1`，影响延迟、价格与合规 |
| **Endpoint（访问域名）** | 服务的访问地址，如 `s3.ap-southeast-1.amazonaws.com`；自建 MinIO 则是自己的域名 |
| **AccessKey（AK/SK）** | `AccessKeyId` + `AccessKeySecret`，签名认证用；SK 必须保密（泄露等于交出整个桶） |
| **Metadata** | 对象的元信息（Content-Type、自定义头等），随对象一起存 |
| **ETag** | 对象内容的标识，通常为 MD5（分段上传时形如 `xxxx-3`），用于校验与并发控制（`If-Match`） |
| **Storage Class** | 存储级别，决定价格与取回速度 |

**对象的限制**：单个对象最大 **5 TB**；单次 PUT 最大 **5 GB**（更大必须分段上传）；分段上传单段最大 5 GB、除最后一段外最小 5 MB，最多 10000 段。

## 四、访问地址的两种写法

```text
# virtual-hosted-style（AWS 推荐，桶名在域名里）
https://my-bucket.s3.ap-southeast-1.amazonaws.com/img/a.png

# path-style（桶名在路径里，自建 MinIO / 兼容服务常用）
https://localhost:9000/my-bucket/img/a.png
```

用 AWS SDK 连自建服务（MinIO、Ceph RGW）时通常要显式打开 path-style：

```js
const s3 = new S3Client({
  endpoint: 'http://localhost:9000',
  region: 'us-east-1',        // MinIO 不校验，但 SDK 必填
  forcePathStyle: true,       // 关键：改用 path-style
  credentials: { accessKeyId: 'admin', secretAccessKey: '12345678' }
})
```

## 五、一致性模型

- **2020 年 12 月之前**：只有新对象的 PUT 是「写后读一致」，覆盖写和删除都是最终一致——这正是当年「随机前缀打散 Key」这类优化技巧存在的原因。
- **现在（2020.12 起）**：S3 对读写提供**强一致性**——新对象 PUT、覆盖写、DELETE 之后，任何后续读请求立即看到最新结果，LIST 也是强一致的。老方案不必再迁就，但看到旧文章里的「加随机前缀」要知道它的历史背景。

## 六、主要能力

| 能力 | 作用 |
| --- | --- |
| **版本控制（Versioning）** | 保留对象的每个历史版本，防误删误覆盖；删除只是打删除标记，可恢复（代价是存储费翻倍） |
| **生命周期（Lifecycle）** | 按规则自动转移存储级别或删除，如「30 天后转 IA，90 天后转 Glacier，365 天后删除」 |
| **存储级别（Storage Class）** | Standard、Intelligent-Tiering、Standard-IA、One Zone-IA、Glacier Instant/Flexible Retrieval、Glacier Deep Archive；越冷越便宜但取回越慢越贵 |
| **分段上传（Multipart Upload）** | 大文件切成多段并发上传、断点续传，是上传大文件的唯一姿势 |
| **预签名 URL（Presigned URL）** | 用 AK/SK 签出一个带过期时间的临时 URL，让浏览器/客户端**直传直读**，流量不过业务服务器 |
| **权限策略（Policy）** | IAM Policy / Bucket Policy / ACL，控制谁能对哪些 Key 做什么 |
| **加密** | SSE-S3 / SSE-KMS / SSE-C 服务端加密，或客户端加密 |
| **跨区域复制（CRR）** | 自动把对象复制到另一个地域的桶，做容灾或多地加速 |
| **静态网站托管** | 桶直接对外提供静态网页（可配索引文档、错误页），常与 CDN 搭配 |
| **事件通知** | 对象创建/删除时触发 Lambda、SQS、SNS、EventBridge，做图片处理、索引等异步链路 |
| **对象锁（Object Lock）** | WORM（一次写入多次读取），合规归档、防勒索用 |
| **传输加速 / CDN** | S3 Transfer Acceleration、CloudFront 等边缘缓存加速分发 |

## 七、权限模型

默认**全部私有**，访问必须被显式授权，来源有四类：

1. **IAM Policy**：授给「用户/角色」，回答「谁能对哪些资源做什么」。
2. **Bucket Policy**：挂在桶上，常用于开放匿名读、限制来源 IP/Referer、强制 HTTPS。
3. **ACL**：老机制，粒度粗，AWS 现已建议关闭（Object Ownership = Bucket owner enforced）。
4. **Presigned URL / STS 临时凭证**：把权限**临时**授给某个 URL 或某次会话，是前端直传的标准做法。

桶策略示例（开放某前缀的匿名读，常用于静态资源）：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/public/*"
    }
  ]
}
```

> 注意：AWS 账号级默认开启 **Block Public Access**。上面这种匿名读策略要先关掉对应开关才生效——这条既是安全网，也是新手最常见的「策略明明写了却 403」的原因。

## 八、命令行操作

```bash
# 配置凭证
aws configure
# AccessKeyId / SecretAccessKey / region / 输出格式

# 桶操作
aws s3 mb s3://my-bucket --region ap-southeast-1   # 建桶
aws s3 ls                                          # 列出所有桶
aws s3 rb s3://my-bucket --force                   # 删除桶（含对象）

# 对象操作
aws s3 cp ./a.png s3://my-bucket/img/a.png         # 上传
aws s3 cp s3://my-bucket/img/a.png ./a.png         # 下载
aws s3 ls s3://my-bucket --recursive --human-readable --summarize
aws s3 rm s3://my-bucket/img/a.png
aws s3 sync ./dist s3://my-bucket --delete         # 目录同步（发布静态站点常用）

# 生成预签名 URL（默认 3600s）
aws s3 presign s3://my-bucket/img/a.png --expires-in 3600

# 底层 API（s3 ls/cp 之外的配置项走 s3api）
aws s3api put-bucket-versioning --bucket my-bucket \
  --versioning-configuration Status=Enabled
aws s3api list-objects-v2 --bucket my-bucket --prefix img/ --max-keys 100
```

MinIO 官方客户端（`mc`，语法类似但更顺手）：

```bash
mc alias set myminio http://localhost:9000 admin 12345678
mc mb myminio/my-bucket
mc cp ./a.png myminio/my-bucket/img/
mc ls myminio/my-bucket --recursive
mc share download --expire 1h myminio/my-bucket/img/a.png
```

## 九、Node.js 中使用

用官方 v3 SDK：

```bash
npm i @aws-sdk/client-s3 @aws-sdk/s3-request-presigner @aws-sdk/lib-storage
```

```js
import { S3Client, PutObjectCommand, GetObjectCommand, DeleteObjectCommand } from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'
import { Upload } from '@aws-sdk/lib-storage'
import { createReadStream } from 'node:fs'

const s3 = new S3Client({
  region: 'ap-southeast-1',
  // 连 MinIO 时加：endpoint: 'http://localhost:9000', forcePathStyle: true
})

// 1. 上传
await s3.send(new PutObjectCommand({
  Bucket: 'my-bucket',
  Key: 'img/a.png',
  Body: createReadStream('./a.png'),
  ContentType: 'image/png',
}))

// 2. 上传大文件：用 lib-storage，自动分段并发 + 重试
await new Upload({
  client: s3,
  params: { Bucket: 'my-bucket', Key: 'video/big.mp4', Body: createReadStream('./big.mp4') },
  partSize: 8 * 1024 * 1024,        // 每段 8MB
  queueSize: 4,                     // 并发 4 段
}).done()

// 3. 生成下载预签名 URL（交给前端直连，无需暴露 AK/SK）
const url = await getSignedUrl(
  s3,
  new GetObjectCommand({ Bucket: 'my-bucket', Key: 'img/a.png' }),
  { expiresIn: 3600 }
)

// 4. 删除
await s3.send(new DeleteObjectCommand({ Bucket: 'my-bucket', Key: 'img/a.png' }))
```

### 前端直传（推荐的上传姿势）

```text
浏览器 ──① 请求签名──▶ 业务服务器（持有 AK/SK，只签名不碰文件）
浏览器 ◀─② 预签名 URL ─
浏览器 ──③ PUT 文件直传 ──▶ S3 ──④ 事件通知──▶ 处理服务/CDN
```

好处：文件不经过业务服务器，省带宽、省内存、不受请求体大小限制、不阻塞 Node 的事件循环（Node 中做文件中转最容易踩的坑）。

## 十、S3 兼容生态

| 产品 | 说明 |
| --- | --- |
| **AWS S3** | 协议源头，功能最全，S3 API 的覆盖度是其他家的参照标准 |
| **MinIO** | 最流行的开源自建方案，部署简单、性能好，是私有化 / 本地开发 / 测试环境的首选 |
| **阿里云 OSS / 腾讯云 COS / 华为云 OBS** | 国内主流，均兼容 S3 API，但控制台与部分高级特性、鉴权签名不完全一致 |
| **Ceph RGW** | Ceph 的对象网关，大规模自建存储集群的常见选择 |
| **Cloudflare R2 / Backblaze B2** | 主打**出口流量免费/便宜**，适合以「读取分发」为主的场景 |
| **JuiceFS S3 网关** | 把 JuiceFS 这个 POSIX 文件系统通过 S3 协议暴露出去，让 S3 生态工具直接读写，见 [minio-juicefs-s3.md](../servers/others-explain/minio-juicefs-s3.md) |

**兼容 ≠ 一致**：不同厂商对 S3 API 的覆盖范围不同（尤其是桶策略、生命周期、分段上传细节、`ListObjects` 的分页参数）。用非 AWS 服务时，最好用 `mc`、`s3cmd` 或 AWS CLI 先跑一遍目标操作验证。

## 十一、典型应用场景

1. **静态资源与 CDN 源站**：图片、视频、JS/CSS 发布到桶里，前面套 CDN，是 S3 最普遍的用法。
2. **用户上传内容的仓库**：配合预签名 URL 直传，业务库里只存 Key/URL。
3. **备份与归档**：数据库全量备份、日志归档，配生命周期自动转 Glacier / 定期删除。
4. **数据湖的存储层**：原始数据先进 S3（schema-on-read），上面挂 Iceberg/Hudi/Delta 表格式，再由 Spark/Flink/Trino 计算——即云上「存算分离」的标准形态。
5. **大数据中间结果 / 交叉集群交换**：Spark、Hive 直接把 S3 当默认文件系统（`s3a://`）。
6. **K8s 中的持久化卷**：通过 CSI 驱动（Mountpoint for S3、s3fs）挂载，但要注意它**不是 POSIX 文件系统**，不适合跑数据库。
7. **容器镜像 / 制品仓库存后端**：Harbor、Nexus 等把 blob 存到 S3 兼容存储。

## 十二、使用时的注意事项（坑）

1. **对象不可局部修改**：想改一个字节也要整对象重传。所以**频繁变动的数据不要放 S3**（如数据库文件、正在写入的日志段），它擅长的是「一次写入，多次读取」。
2. **没有 rename / move**：`mv` 等价于「复制 + 删除」，大对象改名代价很高。Key 命名要一次性想清楚。
3. **单前缀请求速率有上限**：官方指导为**每个前缀**约 3500 次 PUT/COPY/POST/DELETE、5500 次 GET/HEAD 每秒。压测打满时要**打散前缀**（如 `hash/前缀/文件名`），而不是全桶堆在一个目录下。
4. **LIST 一次最多 1000 条**：必须用分页（`ContinuationToken`）或 `listObjectsV2` 的 `StartAfter` 迭代，别指望一次拿全。
5. **请求是要花钱的**：存储费之外还有请求费与流量费。海量小文件（比如每张几 KB、每天几百万次 GET）请求成本可能远超存储成本——小文件可考虑打包、合并或上 CDN 缓存。
6. **公网出流量最贵**：跨区域复制、跨云同步的流量都计费，架构上尽量让计算与存储同地域。
7. **桶名全局唯一且进域名**：AWS 上名字被占了就是被占了，且桶名不能含大写、不能像 IP。
8. **默认私有 + Block Public Access**：公开读要显式开开关再配策略，排查 403 时先看这两处。
9. **预签名 URL 就是凭证**：泄漏出去在有效期内任何人都能用，过期时间要短、粒度要细（限定 Key、方法）。
10. **一致性、可靠性与「删干净」**：开启版本控制后 DELETE 只加删除标记，误删可恢复，但**存储费照算**；要做「真删除」得连版本一起删。
11. **不要把 S3 当 NAS 挂载跑数据库**：POSIX 语义缺失（rename、随机写、锁、fsync 语义），SQLite/MySQL 数据文件放上去极易损坏。

## 十三、选型速查

| 你存的是什么 | 选它 |
| --- | --- |
| 订单、用户、需要事务与关联查询的结构化数据 | MySQL / PostgreSQL |
| 热点数据、缓存、排行榜、分布式锁 | Redis |
| 灵活 schema 的业务文档 | MongoDB |
| 图片、视频、备份、日志、数据湖文件等海量非结构化数据 | **S3 / OSS / COS / MinIO** |
| 需要 POSIX 语义的共享目录（可随机写、可 rename） | NFS / NAS / JuiceFS / HDFS |

> 实际系统里通常是组合：**对象库存文件、数据库存元数据/索引、Redis 存热点**。S3 里只有 Key 和字节，业务查询能力需要靠数据库或上层表格式补足。
