## 0. 先记住一句话

> **IP 负责找到机器，端口负责找到程序，MAC 负责在局域网里认网卡；**
> **内网地址出门要靠 NAT 换成公网地址，名字则要靠 DNS 翻译成 IP。**

后面所有内容，都是围绕这句话展开的。

## 1. 网络通信要用几层地址

### 1.1 三层地址

一次网络通信，至少要回答三个问题：

| 问题 | 用哪个地址 | 作用范围 | 类比 |
|------|-----------|---------|------|
| 数据要送到哪台机器？ | **IP 地址** | 可以跨网络，端到端 | 收货地址（省市区街道门牌） |
| 送到机器上的哪个程序？ | **端口** | 一台机器内部 | 房间号 / 工位号 |
| 在这个局域网里，具体是哪块网卡？ | **MAC 地址** | 只在同一个局域网（二层）内 | 收件人的身份证 / 门禁卡 |

可以把一次通信想成寄快递：

1. 快递单上写**收货地址（IP）**，跨城市也能送到；
2. 到了小区门口，门卫/快递员看的是**具体楼栋和门牌**；
3. 进楼之后，要找的是**具体的人（MAC）**；
4. 人可能住在一个**房间（端口）**里，包裹要交到房间对应的程序手中。

### 1.2 一个容易混淆的点：MAC 会变，IP 一般不变

数据包从你的电脑到服务器，中间会经过很多路由器：

```text
你的电脑 --(以太网帧1)--> 家用路由器 --(帧2)--> 运营商路由器 --(帧3)--> ... --> 服务器
```

- 每一段链路的**源 MAC / 目的 MAC 都会被重写**，因为 MAC 只在当前局域网有效；
- **源 IP / 目的 IP 在整条路径上一般保持不变**（NAT 是例外，后面讲）。

所以：

> MAC 是“这一跳”的地址，IP 是“最终目的地”的地址。

## 2. MAC 地址：网卡的身份证

### 2.1 是什么

MAC 地址（Media Access Control Address），也叫：

- 物理地址（Physical Address）
- 硬件地址（Hardware Address）
- 链路层地址（Link Layer Address）
- 以太网地址（Ethernet Address）

它是**网卡出厂时写入的标识**，用于同一个局域网内的寻址。

### 2.2 格式

MAC 地址是 **48 位（6 字节）**，通常写成 6 组两位十六进制数：

```text
00:1A:2B:3C:4D:5E
```

也可以用 `-` 分隔：

```text
00-1A-2B-3C-4D-5E
```

前 3 组（24 位）是 **OUI（组织唯一标识符）**，代表厂商；后 3 组是厂商分配给这块网卡的编号。

| 部分 | 含义 | 类比 |
|------|------|------|
| `00:1A:2B` | 厂商代码（OUI） | 身份证前几位（地区/发证机关） |
| `3C:4D:5E` | 设备编号 | 身份证后面的个人编号 |

### 2.3 特殊 MAC

| MAC | 含义 |
|-----|------|
| `FF:FF:FF:FF:FF:FF` | 广播地址，发给局域网内所有设备 |
| `01:00:5E:xx:xx:xx` | IPv4 组播映射 |
| `33:33:xx:xx:xx:xx` | IPv6 组播映射 |
| 第一字节最低位为 1 | 组播/广播 |
| 第一字节次低位为 1 | 本地管理地址（软件修改过的 MAC） |

日常最常遇到的是广播 MAC：ARP 请求就靠它。

### 2.4 MAC 在局域网里怎么工作

交换机（Switch）内部维护一张 **MAC 地址表**：

- 收到帧时，记录“源 MAC 来自哪个端口”；
- 转发时，查“目的 MAC 在哪个端口”，只从那个端口发出去；
- 查不到目的 MAC 时，向所有端口泛洪（flood）；
- 广播帧则向所有端口发送。

所以 MAC 的核心作用是：**在同一个局域网内，把帧送到正确的网卡**。

### 2.5 ARP：用 IP 找 MAC

你的电脑知道目的 IP，但网卡发包需要目的 MAC。于是有了 **ARP（Address Resolution Protocol）**。

流程（以 `192.168.1.10` 找 `192.168.1.1` 为例）：

1. 电脑 A 广播 ARP 请求：

   ```text
   “谁是 192.168.1.1？请告诉 192.168.1.10”
   ```

这个请求的以太网目的 MAC 是 `FF:FF:FF:FF:FF:FF`，局域网内所有设备都能收到。

2.目标机器单播回复：

   ```text
   “我是 192.168.1.1，我的 MAC 是 xx:xx:xx:xx:xx:xx”
   ```

3.电脑 A 把结果写入 **ARP 缓存**，后续一段时间内直接使用，不再重复询问。
4.缓存有超时时间，过期后重新询问。

可以用 `arp -a`（Windows/Linux/macOS）查看 ARP 缓存。

IPv6 不再使用 ARP，而是用 **NDP（Neighbor Discovery Protocol）** 完成类似功能。

### 2.6 MAC 地址能改吗？

能。操作系统和网卡驱动允许修改 MAC（通常叫“MAC 伪装”或“克隆 MAC”），常见场景：

- 更换网卡后，让路由器仍认为是原来的设备；
- 某些网络环境要求登记 MAC；
- 测试、虚拟化环境。

但要注意：

- MAC 只是局域网内的转发标识，**不是身份认证**；
- 改 MAC 不代表你能冒充另一台受信任设备，安全策略通常还有认证；
- MAC 冲突会导致局域网通信异常。

### 2.7 怎么查看 MAC

| 系统 | 命令 |
|------|------|
| Windows | `ipconfig /all`，看“物理地址” |
| Windows（只看 MAC） | `getmac` |
| Linux | `ip link` 或 `ip addr` |
| macOS | `ifconfig` |

## 3. IP 地址：网络里的门牌号

### 3.1 是什么

IP 地址（Internet Protocol Address）是**网络层的逻辑地址**，用于在不同网络之间标识一台主机。

关键词是“逻辑”：

- 换一个网络（换 Wi-Fi、换机房、换云服务器），IP 可能就会变；
- IP 由网络配置决定，不是网卡出厂固定。

### 3.2 IPv4 的结构

IPv4 是 **32 位**，写成 4 段十进制数，每段 0–255：

```text
192.168.1.10
```

每一段其实是一个字节（8 位）：

```text
192       .168      .1        .10
11000000  .10101000 .00000001 .00001010
```

4 × 8 = 32 位。

### 3.3 IPv4 的地址分类

历史上把 IPv4 分成 A/B/C/D/E 类，现在基本都用 **CIDR** 表示，但几个概念仍常见：

| 类型 | 范围 | 用途 |
|------|------|------|
| A 类 | `1.0.0.0 – 126.255.255.255` | 早期大型网络 |
| B 类 | `128.0.0.0 – 191.255.255.255` | 早期中型网络 |
| C 类 | `192.0.0.0 – 223.255.255.255` | 早期小型网络 |
| D 类 | `224.0.0.0 – 239.255.255.255` | 组播 |
| E 类 | `240.0.0.0 – 255.255.255.255` | 保留/实验 |

现在更常用的是“私有地址 / 公网地址 / 特殊地址”的分类方式。

### 3.4 私有地址（内网 IP）

私有地址只能在局域网内部使用，不能直接在公网上路由。RFC 1918 规定了三段：

| 网段 | 范围 | 典型场景 |
|------|------|---------|
| `10.0.0.0/8` | `10.0.0.0 – 10.255.255.255` | 大企业、云上 VPC |
| `172.16.0.0/12` | `172.16.0.0 – 172.31.255.255` | 中型网络、容器网络 |
| `192.168.0.0/16` | `192.168.0.0 – 192.168.255.255` | 家庭、小型办公室 |

你家里电脑常见的 `192.168.1.10`、公司电脑常见的 `10.x.x.x`，都是私有地址。

> 私有地址可以重复使用：你家的 `192.168.1.10` 和邻居家的 `192.168.1.10` 不冲突，因为它们各自在自己的局域网里。

### 3.5 公网地址

公网地址全球唯一，由运营商或云厂商分配，可以在互联网上被路由。

公网 IPv4 很紧张，所以：

- 一个家庭通常只分到 **一个** 公网 IP；
- 家里所有设备共用这个公网 IP 上网（NAT）；
- 云服务器通常有一个公网 IP，但操作系统里看到的可能是内网 IP（云厂商做了 NAT）。

### 3.6 特殊地址

| 地址/网段 | 含义 | 说明 |
|-----------|------|------|
| `0.0.0.0` | 未指定地址 / 监听所有网卡 | 不能作为普通目标地址访问；在服务配置中表示“所有地址” |
| `127.0.0.0/8` | 回环地址 | 最常用 `127.0.0.1`，指向本机 |
| `255.255.255.255` | 本地广播 | 只在本局域网广播 |
| `169.254.0.0/16` | 链路本地地址 | 没拿到 DHCP 时自动分配，常见于“网络有问题” |
| `224.0.0.0/4` | 组播地址 | 一对多通信 |
| `100.64.0.0/10` | 运营商级 NAT（CGNAT） | 运营商大内网使用 |
| `198.18.0.0/15` | 基准测试保留 | 一般不会出现在真实网络 |

### 3.7 IPv6 简介

IPv6 是 **128 位**，写成 8 组十六进制：

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

可以简写：

- 每组开头的 0 可以省略；
- 连续的全 0 组可以用 `::` 代替，但只能出现一次：

```text
2001:db8:85a3::8a2e:370:7334
```

常见 IPv6 地址：

| 地址 | 含义 |
|------|------|
| `::1` | 回环地址（相当于 IPv4 的 127.0.0.1） |
| `::` | 未指定地址 |
| `fe80::/10` | 链路本地地址（每块网卡自动生成） |
| `2000::/3` | 全球单播地址 |
| `ff00::/8` | 组播地址 |

IPv6 的特点：

- 地址极多，不再需要 NAT 来“省地址”；
- 没有广播，用组播和 NDP；
- 主机可以自动配置地址（SLAAC）；
- 防火墙策略更重要，因为每台设备都可能有公网地址。

## 4. 子网掩码、网段与网关

### 4.1 子网掩码是干什么的

IP 地址 = **网络部分 + 主机部分**，子网掩码用来划分这两部分。

以 `192.168.1.10/24` 为例：

- `/24` 表示前 24 位是网络部分；
- 等价于子网掩码 `255.255.255.0`；
- 网络地址是 `192.168.1.0`；
- 广播地址是 `192.168.1.255`；
- 可用主机地址是 `192.168.1.1 – 192.168.1.254`。

```text
192.168.1.10
└── 24 位 ──┘└8位┘
   网络部分    主机部分
```

### 4.2 怎么判断两台机器是否在同一网段

把 IP 和子网掩码做“按位与”，得到网络地址：

```text
192.168.1.10  AND  255.255.255.0  =  192.168.1.0
192.168.1.20  AND  255.255.255.0  =  192.168.1.0
```

网络地址相同 → 同一网段 → 可以直接通信（通过 ARP 找 MAC）。

```text
192.168.2.20  AND  255.255.255.0  =  192.168.2.0
```

网络地址不同 → 不同网段 → 需要经过网关转发。

### 4.3 子网划分例子

`192.168.1.0/24` 可以分成两个 `/25`：

| 子网 | 网络地址 | 可用范围 | 广播地址 |
|------|---------|---------|---------|
| 前半 | `192.168.1.0/25` | `.1 – .126` | `.127` |
| 后半 | `192.168.1.128/25` | `.129 – .254` | `.255` |

虽然它们看起来都在 `192.168.1.x`，但 `/25` 下属于两个不同网段，互相通信也要经过路由器。

### 4.4 网关是什么

**默认网关**是“本网段通往外部的出口”，通常是路由器的 LAN 口地址，例如 `192.168.1.1`。

发送数据时的判断：

```text
目的 IP 和我同一网段？
  ├─ 是：ARP 找目的 IP 的 MAC，直接发
  └─ 否：ARP 找网关的 MAC，把包交给网关
```

注意：跨网段时，**目的 IP 仍然是最终服务器 IP**，只是以太网帧的目的 MAC 变成了网关的 MAC。

网关收到包后：

1. 查路由表，决定下一跳；
2. 把 TTL 减 1；
3. 重写二层帧头（新的源/目的 MAC）；
4. 从对应接口发出去。

TTL 的作用是防止数据包在网络里无限循环。

### 4.5 路由表

每台机器都有一张路由表，决定“去哪个网段走哪个接口/网关”。

Windows：

```bash
route print
```

Linux：

```bash
ip route
```

典型输出：

```text
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0
```

- `default` 就是默认路由，匹配不上其他规则时走它；
- 更具体的路由优先级更高。

## 5. 端口：一台机器上的房间号

### 5.1 端口是什么

端口是 **16 位数字**，范围 `0 – 65535`。

IP 定位到机器，端口定位到机器上的某个程序（更准确说是某个 socket）。

```text
192.168.1.10:8080
└──── IP ────┘ └端口┘
```

同一台机器可以同时运行 Web、SSH、数据库，它们用不同端口区分。

### 5.2 端口分类

| 范围 | 名称 | 说明 |
|------|------|------|
| `0 – 1023` | 知名端口（Well-known） | 系统服务常用，绑定通常需要管理员权限 |
| `1024 – 49151` | 注册端口（Registered） | 应用注册使用 |
| `49152 – 65535` | 动态/临时端口（Ephemeral） | 客户端发起连接时临时使用 |

不同系统的临时端口范围可以调整，比如 Linux 的 `net.ipv4.ip_local_port_range`。

### 5.3 常见端口

| 端口 | 协议 | 服务 |
|------|------|------|
| 20/21 | TCP | FTP 数据/控制 |
| 22 | TCP | SSH |
| 23 | TCP | Telnet（不安全，少用） |
| 25 | TCP | SMTP |
| 53 | TCP/UDP | DNS |
| 67/68 | UDP | DHCP |
| 80 | TCP | HTTP |
| 110 | TCP | POP3 |
| 143 | TCP | IMAP |
| 443 | TCP | HTTPS |
| 3306 | TCP | MySQL |
| 5432 | TCP | PostgreSQL |
| 6379 | TCP | Redis |
| 8080 | TCP | 常见备用 HTTP / 代理 |
| 27017 | TCP | MongoDB |

### 5.4 五元组

一条 TCP 连接由五元组唯一标识：

```text
源 IP、源端口、目的 IP、目的端口、协议
```

例如：

```text
192.168.1.10:52341  →  47.96.1.20:443  TCP
```

这也是 NAT 能工作的基础：路由器通过改写源 IP/端口，区分家里不同设备的不同连接。

### 5.5 监听地址：0.0.0.0 与 127.0.0.1

服务启动时要绑定一个地址：

| 监听地址 | 含义 | 谁能访问 |
|---------|------|---------|
| `127.0.0.1:8080` | 只监听回环 | 只有本机能访问 |
| `0.0.0.0:8080` | 监听所有 IPv4 网卡 | 本机、局域网、公网（在防火墙允许时） |
| `[::]:8080` | 监听所有 IPv6 网卡 | 类似上一行 |
| `192.168.1.10:8080` | 只监听某块网卡 | 只有该网卡对应的网络能访问 |

这就是为什么：

- 本地 `curl 127.0.0.1:8080` 正常；
- 同事却访问不了你的服务；
- 把监听地址从 `127.0.0.1` 改成 `0.0.0.0` 后就可以了（还要看防火墙）。

### 5.6 端口冲突

同一个 IP + 端口 + 协议，同时只能被一个程序监听（除非使用 SO_REUSEPORT 等特殊选项）。

报错通常是：

```text
Address already in use
```

排查：

```bash
# Linux
ss -lntup | grep 8080

# Windows
netstat -ano | findstr :8080
```

## 6. 内网 IP、公网 IP 与 NAT

### 6.1 为什么需要 NAT

IPv4 地址只有约 43 亿个，早就不够用。NAT（Network Address Translation，网络地址转换）让多台设备共享一个公网 IP。

家里的典型结构：

```text
电脑 192.168.1.10 ┐
手机 192.168.1.11 ├── 路由器（内网 192.168.1.1 / 公网 203.0.113.7）── 互联网 ── 服务器 47.96.1.20
电视 192.168.1.12 ┘
```

外部看到的所有流量，来源都是 `203.0.113.7`。

### 6.2 NAT 具体做了什么

以电脑访问网站为例：

1. 电脑发出：

   ```text
   192.168.1.10:52341 → 47.96.1.20:443
   ```

2. 路由器把源地址改写成公网地址，并分配一个公网端口：

   ```text
   203.0.113.7:61001 → 47.96.1.20:443
   ```

   同时在 NAT 表里记录映射：

   ```text
   203.0.113.7:61001  ↔  192.168.1.10:52341
   ```

3. 服务器看到的来源是 `203.0.113.7:61001`。
4. 回包到达路由器，路由器查 NAT 表，改回：

   ```text
   47.96.1.20:443 → 192.168.1.10:52341
   ```

5. 电脑收到回包。

这种同时改写 IP 和端口的 NAT 叫 **NAPT / PAT（端口地址转换）**，家庭路由器基本都是这种。

### 6.3 NAT 带来的限制

- **外网不能主动连内网设备**：没有 NAT 表项，路由器不知道该转给谁。
- 想让外网访问家里设备，需要：
  - 路由器上做**端口映射（Port Forwarding）**；
  - 或使用内网穿透工具；
  - 或把服务放到有公网 IP 的云服务器上。
- 一些 P2P、VoIP、在线游戏需要 NAT 穿透（STUN/TURN/UPnP）。
- 运营商级 NAT（CGNAT）会让情况更复杂，因为你自己都没有独立公网 IP。

### 6.4 我到底有没有公网 IP

判断方法：

1. 在路由器管理页面看 WAN 口 IP；
2. 在浏览器搜索“我的 IP”，看外部看到的 IP；
3. 两者一致，且不是私有地址，才可能是公网 IP；
4. 如果 WAN 口是 `100.64.x.x`、`10.x.x.x`、`192.168.x.x`，通常说明你在运营商大内网。

## 7. 服务器上的地址

### 7.1 域名只是名字

人记不住 `47.96.1.20`，所以用域名 `www.example.com`。真正通信仍然靠 IP。

流程：

```text
浏览器输入域名
  → 查本地 hosts
  → 查 DNS 缓存
  → 问 DNS 服务器
  → 拿到 IP
  → 向 IP 发起连接
```

### 7.2 DNS 解析过程

简化版：

1. 浏览器/操作系统缓存；
2. 本机 `hosts` 文件；
3. 本地 DNS 服务器（运营商或公共 DNS）；
4. 若本地没有缓存，递归查询：
   - 根域名服务器；
   - 顶级域（.com）服务器；
   - 权威 DNS 服务器；
5. 返回记录并缓存（受 TTL 控制）。

常见记录：

| 记录 | 含义 |
|------|------|
| `A` | 域名 → IPv4 |
| `AAAA` | 域名 → IPv6 |
| `CNAME` | 别名 → 另一个域名 |
| `MX` | 邮件服务器 |
| `NS` | 该域名的权威服务器 |
| `TXT` | 文本记录（验证、SPF 等） |

### 7.3 云服务器的“公网 IP”可能不在网卡上

这是初学者最容易困惑的点之一。

很多云服务器（阿里云、腾讯云、AWS 等）的实际情况是：

```text
公网 IP 47.96.1.20  ──(云网关 NAT)──  内网 IP 10.0.0.5  ──  服务器网卡
```

- 你在云控制台看到“公网 IP”；
- 登录服务器执行 `ip addr`，只看到 `10.0.0.5`；
- 公网 IP 是云平台通过 NAT/弹性 IP 映射的，**并不配置在操作系统网卡上**。

所以：

- 服务器上抓包看到的目的地址通常是内网 IP；
- 不能用“网卡上没有公网 IP”来判断公网 IP 无效；
- 端口监听 `0.0.0.0` 仍然能收到公网流量。

### 7.4 服务器常见的几个地址

| 地址 | 作用 | 注意 |
|------|------|------|
| 公网 IP / EIP | 给外部访问 | 云上通常是 NAT 映射 |
| 内网 IP / VPC IP | 同一内网内通信 | 数据库、内部服务常用 |
| `127.0.0.1` | 本机回环 | 不经过网卡 |
| `0.0.0.0` | 监听所有网卡 | 不是可访问的目标地址 |
| 内网 DNS 名称 | 服务发现 | 如 `db.internal`、K8s Service 名 |

### 7.5 服务器连不上时的排查顺序

从外到内：

1. **DNS 是否正确**：`nslookup 域名` 是否返回正确 IP；
2. **公网 IP 是否正确**：是否绑定了 EIP，是否换了 IP；
3. **安全组 / 防火墙**：云厂商安全组、系统防火墙是否放行端口；
4. **服务是否监听正确地址**：`ss -lntp`，看是 `127.0.0.1` 还是 `0.0.0.0`；
5. **端口是否对**：80/443/自定义端口；
6. **进程是否存活**：`ps`、`systemctl status`；
7. **路由/NAT**：是否能 `ping` 通，`traceroute` 卡在哪；
8. **应用日志**：是否有报错、是否启动完成。

## 8. “虚拟地址”到底指什么

“虚拟地址”是个很模糊的词，至少有以下几种完全不同的含义。听到时一定要先问：**在哪个上下文里？**

### 8.1 回环地址：127.0.0.1

- `127.0.0.0/8` 整个网段都表示“本机”；
- 最常用 `127.0.0.1`，主机名 `localhost`；
- 数据不经过物理网卡，走内核回环接口；
- 即使没插网线、没联网，也能访问本机服务；
- IPv6 对应 `::1`。

常见用途：

- 本地开发测试；
- 数据库只允许本机连接；
- 代理、端口转发。

注意区别：

```text
127.0.0.1:3306  → 只有本机能连数据库
0.0.0.0:3306    → 所有网卡都监听，外网也可能连（取决于防火墙）
```

### 8.2 虚拟机的地址

虚拟机（VMware、VirtualBox、Hyper-V、KVM 等）会在宿主机里创建虚拟网卡和虚拟交换机，给虚拟机分配“虚拟网络”的 IP。

常见三种网络模式：

| 模式 | 虚拟机 IP 从哪来 | 谁能访问虚拟机 | 典型网段 |
|------|-----------------|---------------|---------|
| 桥接（Bridged） | 和宿主机同一个物理局域网，由路由器 DHCP 分配 | 局域网内其他设备都能访问 | 与宿主机同网段，如 `192.168.1.x` |
| NAT | 虚拟机软件自己分配，VM 通过宿主机上网 | 虚拟机能出去；外面默认进不来 | VMware 常见 `192.168.x.x`；VirtualBox 默认 `10.0.2.15`，网关 `10.0.2.2` |
| 仅主机（Host-only） | 虚拟机软件自己分配 | 只有宿主机和虚拟机互通 | VMware `VMnet1` 常见 `192.168.x.x` |
| 内部网络（Internal） | 虚拟机软件自己分配 | 只有同一内部网络里的虚拟机互通 | 自定义 |

补充：

- 桥接模式下，虚拟机在局域网里就像另一台独立电脑；
- NAT 模式下，虚拟机访问外网要经过宿主机/虚拟 NAT 设备，外部主动访问需要端口映射；
- 仅主机模式适合做实验，不连外网；
- Hyper-V 会创建 `vEthernet` 虚拟交换机；
- 宿主机 ping 不通虚拟机时，先看模式、虚拟机防火墙、IP 是否同网段。

### 8.3 容器与 Kubernetes 的地址

**Docker 默认网络：**

- 创建网桥 `docker0`；
- 默认网段常见 `172.17.0.0/16`；
- 每个容器有一对 `veth`（虚拟网线），一端在容器里，一端接在网桥上；
- 容器可以访问外网（通过宿主机 NAT）；
- 外部访问容器需要 `-p 宿主端口:容器端口` 做端口映射。

```text
宿主机
 ├─ docker0 172.17.0.1
 ├─ 容器 A 172.17.0.2
 └─ 容器 B 172.17.0.3
```

**Kubernetes：**

| 概念 | 说明 | 典型地址 |
|------|------|---------|
| Pod IP | 每个 Pod 一个 IP，由 CNI 插件分配 | Flannel 默认 `10.244.0.0/16` |
| Service ClusterIP | 虚拟 IP，只在集群内部有效 | kubeadm 默认 `10.96.0.0/12` |
| NodePort | 在每个节点上开的端口 | 默认 `30000 – 32767` |
| Ingress / LB | 集群入口 | 由 Ingress Controller 或云 LB 提供 |
| CoreDNS | 集群内 DNS | `服务名.命名空间.svc.cluster.local` |

关键点：

- **ClusterIP 是“虚拟”的**：没有任何一台机器的网卡上真的配置了这个 IP；
- kube-proxy 通过 iptables/IPVS 规则把访问 ClusterIP 的流量转发到后端 Pod；
- 所以你在集群外 `ping ClusterIP` 通常不通，这是正常的；
- Pod IP 会随 Pod 重建而变化，Service 提供稳定入口；
- 集群内访问服务用 Service 名，不要写死 Pod IP。

### 8.4 虚拟 IP（VIP）

VIP（Virtual IP）是一个**不固定绑定在某台物理机上的地址**，常见于高可用和负载均衡：

- keepalived + VRRP：主备两台机器共享一个 VIP，主挂了 VIP 漂移到备；
- LVS / HAProxy / Nginx：对外暴露一个 VIP，后端挂多台真实服务器；
- 云负载均衡：提供一个服务地址，后端是多台实例；
- K8s Service ClusterIP 也可以理解为一种 VIP。

VIP 的“虚拟”体现在：

- 它不属于某块固定网卡；
- 它可以在机器之间漂移；
- 客户端只需要知道 VIP，不关心后端是谁。

### 8.5 内存里的“虚拟地址”（容易混淆）

操作系统给进程看到的地址，比如：

```text
0x7ffd5c3a9b40
```

这是**虚拟内存地址**，由 MMU 和页表映射到物理内存：

```text
进程虚拟地址  →  页表  →  物理内存地址（或磁盘 swap）
```

它和网络里的 IP、MAC 完全无关。看到“虚拟地址”时，如果在讲进程、内存、指针、分页，那就是这个含义。

### 8.6 一张表区分

| 说法 | 实际含义 | 是否网络地址 |
|------|---------|-------------|
| `127.0.0.1` | 回环地址 | 是 |
| 虚拟机 IP | 虚拟网络里的 IP | 是 |
| Docker 容器 IP | 容器网络里的 IP | 是 |
| K8s ClusterIP | 集群虚拟服务地址 | 是（虚拟） |
| VIP | 可漂移的虚拟 IP | 是（虚拟） |
| 虚拟内存地址 | 进程地址空间 | 否 |

## 9. 一次网页访问的完整旅程

以 `http://example.com` 为例（简化）：

### 第一步：解析域名

1. 浏览器查缓存、系统缓存、hosts；
2. 向 DNS 服务器查询 `example.com` 的 A 记录；
3. 得到 `47.96.1.20`。

### 第二步：准备连接

1. 操作系统选择源 IP（本机网卡地址）和临时源端口；
2. 目标：`47.96.1.20:80`；
3. 比较目标 IP 和本机网段：
   - 不在同一网段 → 走默认网关。

### 第三步：ARP 找网关

1. 本机广播 ARP：“谁是 192.168.1.1？”；
2. 路由器回复自己的 MAC；
3. 本机组装以太网帧：

   ```text
   源 MAC：本机网卡
   目的 MAC：路由器
   源 IP：192.168.1.10
   目的 IP：47.96.1.20
   ```

### 第四步：局域网转发

1. 帧到达交换机；
2. 交换机按目的 MAC 转发到路由器端口；
3. 路由器收到帧，剥掉二层头；
4. 查路由表，决定下一跳；
5. TTL 减 1；
6. 做 NAT：源 IP/端口改写成公网地址；
7. 重新封装二层帧，发往运营商。

### 第五步：互联网路由

1. 数据包经过多个路由器；
2. 每跳重写 MAC，IP 保持（NAT 已改写源地址）；
3. TTL 持续减少，到 0 则丢弃并返回 ICMP 超时；
4. 最终到达服务器所在网络。

### 第六步：到达服务器

1. 云网关做 DNAT/端口映射，把公网 IP 转到服务器内网 IP；
2. 服务器网卡收到包；
3. 内核检查目的 IP、端口、监听 socket；
4. 交给对应进程。

### 第七步：建立连接

1. TCP 三次握手：

   ```text
   SYN →
   ← SYN+ACK
   ACK →
   ```

2. 如果是 HTTPS，再进行 TLS 握手；
3. 发送 HTTP 请求。

### 第八步：返回响应

1. 服务器返回 HTTP 响应；
2. 数据包沿原路返回；
3. 经过云网关、互联网、家用路由器；
4. 路由器查 NAT 表，把目的地址改回 `192.168.1.10:52341`；
5. 浏览器收到响应，渲染页面。

## 10. 查看与排查：常用命令

### 10.1 查看本机网络信息

| 想看什么 | Windows | Linux | macOS |
|---------|---------|-------|-------|
| IP、掩码、网关、MAC | `ipconfig /all` | `ip addr`、`ip route` | `ifconfig`、`netstat -rn` |
| 只看 MAC | `getmac` | `ip link` | `ifconfig` |
| 路由表 | `route print` | `ip route` | `netstat -rn` |
| ARP 缓存 | `arp -a` | `ip neigh`、`arp -a` | `arp -a` |
| DNS 配置 | `ipconfig /all` | `resolvectl status`、`cat /etc/resolv.conf` | `scutil --dns` |
| 端口监听 | `netstat -ano` | `ss -lntup` | `lsof -i -P` |

### 10.2 连通性测试

```bash
# 测试 IP 是否可达
ping 47.96.1.20

# 测试域名解析 + 连通
ping www.example.com

# 只查 DNS
nslookup www.example.com
dig www.example.com

# 看路径经过哪些路由器
tracert www.example.com      # Windows
traceroute www.example.com   # Linux/macOS

# 测试端口是否开放
telnet 47.96.1.20 80         # Windows/Linux
nc -zv 47.96.1.20 80         # Linux/macOS
curl -v http://47.96.1.20    # 看 HTTP 细节
```

### 10.3 抓包

```bash
# Linux：抓某块网卡上的 80 端口流量
tcpdump -i eth0 -nn port 80

# 抓 ARP
tcpdump -i eth0 -nn arp

# Windows：可用 Wireshark 图形界面
```

抓包能直接看到：

- 源/目的 IP；
- 源/目的 MAC；
- 端口；
- TCP 握手是否完成；
- 是否有 RST、超时、重传。

### 10.4 排查思路清单

**能 ping 通 IP，但域名不行？**

→ DNS 问题。检查 `nslookup`、`/etc/resolv.conf`、hosts。

**能 ping 通，但端口连不上？**

→ 服务没监听、监听在 `127.0.0.1`、防火墙/安全组、端口写错。

**域名解析出的 IP 不对？**

→ DNS 缓存、hosts、CDN、域名解析配置。

**家里设备上不了网？**

→ 看 IP 是否是 `169.254.x.x`（DHCP 失败）、网关是否可达、DNS 是否可用。

**虚拟机/容器连不上？**

→ 网络模式、NAT/端口映射、防火墙、是否同网段。

**服务器突然连不上？**

→ 安全组变更、服务挂掉、磁盘满、CPU/内存打满、IP 被封、证书过期。

## 11. 常见问题 FAQ

### Q1：为什么我的电脑 IP 是 192.168 开头？

`192.168.0.0/16` 是私有地址，只在你所在的局域网有效。互联网上别人看到的是路由器或运营商的公网 IP。

### Q2：为什么重启路由器后，电脑 IP 变了？

路由器用 DHCP 自动分配地址，并设置租期。想固定可以在路由器里做 DHCP 静态绑定（按 MAC 绑定 IP）。

### Q3：服务器为什么既有公网 IP 又有内网 IP？

云厂商用 NAT 把公网 IP 映射到内网 IP：

- 公网 IP：外部访问入口；
- 内网 IP：同一 VPC/机房内部通信，速度快、可隔离。

### Q4：0.0.0.0 和 127.0.0.1 有什么区别？

- `127.0.0.1`：只代表本机，服务只监听它时，别的机器连不上；
- `0.0.0.0`：表示“所有网卡”，服务监听它时，所有可达的网络都能连（还要看防火墙）；
- 在路由表里，`0.0.0.0/0` 表示默认路由，是另一个含义。

### Q5：为什么 localhost 能访问，别人访问不了？

服务监听在 `127.0.0.1` 而不是 `0.0.0.0`，或者防火墙只允许本机。

### Q6：MAC 地址能改吗？

可以，软件可以伪装。但 MAC 不是安全凭证，不能靠它做身份认证。

### Q7：为什么全家的设备对外显示同一个 IP？

因为家里所有设备通过 NAT 共享路由器的公网 IP。

### Q8：为什么虚拟机会拿到 10.0.2.15 / 192.168.x.x？

这是虚拟机软件 NAT/仅主机模式分配的私有地址。想让它像局域网里的独立电脑一样，改用桥接模式。

### Q9：为什么 K8s 的 ClusterIP ping 不通？

ClusterIP 是虚拟服务地址，没有网卡真正持有它，只有集群内的转发规则认识它。用 `curl` 访问 Service 端口，或在集群内测试。

### Q10：169.254 开头的地址是什么？

链路本地地址（APIPA），通常是 DHCP 没拿到地址时自动生成的。看到它一般说明网络配置有问题。

### Q11：IP 冲突会怎样？

同一局域网里两台设备用同一个 IP，会导致 ARP 混乱、间歇性断网、连接被重置。排查可用 `arp -a` 看 MAC 是否变化。

### Q12：IPv6 会取代 IPv4 吗？

会逐步替代，但 IPv4 和 NAT 还会长期共存。很多网络是双栈（同时启用 IPv4 和 IPv6）。

### Q13：为什么服务器上 `ip addr` 看不到公网 IP？

云服务器的公网 IP 往往由云网关 NAT 映射，不配置在操作系统网卡上。

### Q14：端口被占用怎么办？

```bash
# Linux
ss -lntup | grep 8080
kill <PID>

# Windows
netstat -ano | findstr :8080
taskkill /PID <PID> /F
```

### 12.1 私有地址与特殊地址

| 网段 | 说明 |

| `::1` | IPv6 回环 |
| `fe80::/10` | IPv6 链路本地 |

### 12.2 地址类型对比

| 类型 | 例子 | 会变吗 | 作用范围 | 谁分配 |
|------|------|-------|---------|-------|
| MAC | `00:1A:2B:3C:4D:5E` | 出厂固定，可软件改 | 局域网 | 厂商 |
| 私有 IP | `192.168.1.10` | 会（DHCP/换网络） | 局域网 | 路由器/管理员 |
| 公网 IP | `47.96.1.20` | 可能（重新分配） | 全球 | 运营商/云厂商 |
| 回环 | `127.0.0.1` | 固定 | 本机 | 系统 |
| 端口 | `443` | 固定/可配置 | 单机 | 程序/系统 |
| VIP | `10.0.0.100` | 可漂移 | 服务集群 | 负载均衡/keepalived |
| ClusterIP | `10.96.0.10` | 固定（Service 生命周期内） | K8s 集群 | K8s |

## 总结

再回到那句话：

> **IP 找到机器，端口找到程序，MAC 在局域网里认网卡；NAT 负责出门，DNS 负责翻译名字。**

学习建议：

1. 先用手边的电脑执行 `ipconfig /all` / `ip addr`，把 IP、掩码、网关、MAC 对上号；
2. 用 `ping`、`arp -a`、`tracert` 观察真实流量；
3. 在家用路由器上看看 DHCP 和端口映射；
4. 搭一台虚拟机或 Docker，观察 NAT 和桥接的区别；
5. 有机会再深入路由、NAT 表、K8s Service 的转发规则。

把“地址”理解成不同层级的“定位方式”，很多网络概念就串起来了。
