## 服务器

是作为实体的硬件存在的，一般的服务器都是部署在专有的机房之中，服务器的组成一般与个人用PC机相同，只不过侧重点不同，个人PC机更侧重于娱乐和个人应用，而服务器更加倾向于性能、安全、散热、稳定等指标
一般服务器上会安装诸如linux或者winserver（windows的服务器版本）等系统，并在服务器上安装相应功能的软件，提供不同的服务，比如搭建网站需要
**安装数据库、http服务**等等，划分空间进行存储，http网站服务等。

### 虚拟主机

顾名思义，由于实体服务器需要更高的成本，比如硬件费用，机房租用费用，以及人员维护成本等。为了更好的推广互联网，大的互联网公司推出了虚拟主机的服务，也就是说你不需要硬件、带宽、运维等就可以使用服务器的资源搭建自己的服务，当然低成本的同时性能也会相应的降低。因为一般的虚拟主机都是
**同一台服务器上虚拟出来的系统**以供人们使用，动态修改参数配置。

## 其他

- CPU：**处理器**，类似商店里的营业员，单核一个人，双核2个人，四核4个人；擅长串行通用计算，适合逻辑控制和少量线程

- GPU：**处理器**，擅长大规模并行计算，适合处理密集型数据任务

- 显卡：处理图像，类似商店外边的女模特，脸蛋好，长的越精致越贵。**信号转换显示图形**，**独立显卡**个性化设计，娱乐，绘图等

- 内存：类似店铺营业间，越大摆放的商品越多。**暂存区**

- 硬盘：类似店铺的：**仓库**，越大，摆放的越多。**固态硬盘**

**硬盘和内存的区别**，内存是商品展示（数据从硬盘搬到内存暂存），CPU（类似营业员）将内存的数据进行处理，如果缺数据了，就从硬盘搬到内存，顺手将内存暂时不用的数据搬回硬盘（仓库）。在硬盘（仓库）一个区域划出一块地方，用于暂时保存数据（暂时不用或即将要用的），这个区域就叫虚拟内存。

- 速率：数据传输（数据是指0和1）的速率，比如你用迅雷下载，1兆每秒，来衡量目前数据传输的快慢

- 带宽：网络带宽是指在单位时间（一般指的是1秒钟）内能传输的数据量，比如说你家的电信网络是100兆比特，意思是，一秒内最大的传输速率是100兆比特。

- 吞吐量：表示在单位时间内通过某个网络（或信道、接口）的数据量。

- 时延：时延是指数据（报文/分组/比特流）从网络（或链路）的一端传送到另一端所需的时间，单位是s：发送、传播、排队、处理、往返

## OSI层

![osi](./imgs/OSI.png)

1、物理层

物理层更多的**是规定传输媒体接口的标准**，他并不管物理介质具体是什么，比如电线杆上是光纤还是双绞线，只要你能按物理层规定的标准传输数据就行。

- 计算机传输数据需要先把电信号转为光信号，然后光信号快到服务器的时候，再把光信号转为电信号。
- 线路上传输的信号功率会逐渐衰减，衰减到一定程度时将造成信号失真，因此会导致接收错误
- 中继器可以对信号进行再生和还原，增加信号的传输距离

2、数据链路层

主要功能：

- 封装成帧：封装的网络数据包，在链路层就叫数据帧
- 透明传输：帧的数据部分可能有跟帧首部完全一样的字符，这时候就要采取一定的措施，让接受方不要被被误导，能让接收方知道哪些是帧的首部哪些是帧的数据
- 差错控制：差错控制的方法有CRC循环冗余码
- 差错纠正：丢失后，通过重新发送没有的文件来纠正
- 流量控制：比如说发送方发送速度特别快，接收方接收速度特别慢，会造成传输出错

3、以太网、无线网

以太网是一种局域网技术，其规定了访问控制方法、传输控制协议、网络拓扑结构、传输速率等，完成数据链路层和物理层的一些内容，它采用一种称作CSMA/CD的媒体接入方法（后面会介绍），另外的一些局域网技术，比如无线局域网等

- 无连接。发送方和接收方不建立连接。
- 不可靠。接收方不向发送方进行确认，差错帧直接丢弃。

无线局域网WLAN是利用无线电波、激光和红外线等无线通信技术来构建的局域网

## 集群

集群是指将**一组独立的计算机（服务器）通过网络连接起来，让它们协同工作，对外表现为一个统一的整体**。

- 高并发（性能）：一台服务器能支撑的并发请求是有限的。当用户量激增，单机会成为瓶颈。集群通过多台服务器分担请求，将流量分散。
- 高可用（可靠性）：单机一旦宕机（硬件故障、断电等），整个服务就不可用了。集群中如果某台机器宕机，其他机器可以立刻接管流量，用户几乎无感知，这被称为“故障转移”。
- 可扩展（伸缩性）：当业务增长时，集群可以在不中断服务的情况下，通过增加机器（横向扩展）来提升整体能力，而不是只能更换更贵的机器（纵向扩展）。

集群的常见分类：

- 负载均衡集群：在服务器前面加一个“分发器”（如Nginx），将请求按照一定策略（轮询、最少连接数等）分发给后面的多台服务器。
- 高可用性集群：主要目的是保证服务持续可用，通常采用主备模式（如一台主服务器工作，另一台备服务器实时同步数据，主服务器宕机时备服务器立刻接管）。
- 高性能计算集群：将多台服务器的计算能力聚合，共同完成一个复杂的计算任务（如天气预报、基因测序）。

**节点**：集群中的每一台服务器称为一个“节点”。

**状态管理**：集群中一个难点是“会话保持”（Session）。如果用户第一次登录在节点A，下一次请求被分发到了节点B，节点B不认识这个用户，就会要求重新登录。解决方案通常有：

- 会话粘滞：让同一个用户的请求始终分发到同一个节点。
- 会话共享：将Session信息存储在一个所有节点都能访问的中间件中（如Redis）。

**数据一致性**：如果集群中的多台服务器需要访问共享数据（如数据库），数据库本身也需要成为集群，并解决数据同步、主从复制、分库分表等复杂问题。

## 程序

- **程序**：静态的代码和数据，放在磁盘上，比如 `.exe`、`.out`、`.py` 文件。
- **进程**：程序的一次运行实例，是操作系统分配资源的基本单位。
- **线程**：进程内部的执行流，是 CPU 调度执行的基本单位。
- **协程**：用户态的轻量级执行流，由语言运行时、库或事件循环来调度。
- **并发**：多个任务在同一时间段内交替推进。单核也能并发。
- **并行**：多个任务在同一时刻真正同时执行。通常需要多核 CPU。

程序本身只是磁盘上的文件，不能直接“跑”。运行大致经历：

1. **编译/解释**：源代码变成机器能执行的指令，或由解释器边解释边执行。
2. **加载**：操作系统把可执行文件加载到内存。
3. **创建进程**：为它建立进程控制块 PCB，分配虚拟地址空间、打开文件等资源。
4. **调度**：进程进入就绪队列，CPU 调度器选中它后开始执行。
5. **执行**：CPU 不断取指令、译码、执行，可能读写内存、调用系统调用、等待 I/O。
6. **结束**：进程退出，操作系统回收内存、文件等资源。

### 进程

进程可以理解为“正在运行的程序实例”。它拥有：

- 独立的**虚拟地址空间**：代码段、数据段、堆、栈等。
- **进程控制块 PCB**：记录进程 ID、状态、寄存器、页表、优先级等。
- 资源：打开的文件、网络连接、信号、内存等。
- 生命周期：创建、就绪、运行、阻塞、终止。

特点：

- 进程之间**相互隔离**，一个进程崩溃通常不影响另一个进程。
- 进程是**资源分配的基本单位**。
- 同一个程序可以运行成多个进程，例如打开多个浏览器窗口，可能就是多个进程。
- 进程之间通信需要 **IPC**，如管道、消息队列、共享内存、信号、Socket 等。

### 线程

线程是进程中的一条执行流。一个进程至少有一个线程，叫主线程。一个进程可以有多个线程。

线程共享进程的资源：

- 代码段、全局变量、堆
- 打开的文件、网络连接
- 地址空间

但每个线程有自己独立的内容：

- 程序计数器 PC
- 寄存器
- 栈
- 线程 ID、状态、优先级

特点：

- 线程是 **CPU 调度和执行的基本单位**。
- 同一进程内线程切换开销比进程切换小。
- 多线程可以并发执行，在多核上可以并行执行。
- 线程之间通信方便，直接读写共享变量即可，但必须同步，否则会出现**竞态条件、死锁**等问题。
- 一个线程崩溃，可能导致整个进程崩溃。

多线程不一定更快：

- 如果是 CPU 密集任务，多核并行才有明显收益。
- 如果是 I/O 密集任务，多线程可以重叠等待时间，提高吞吐。
- 线程太多会带来切换开销、锁竞争、内存占用等问题。

CPU 一次通常只能执行一个线程。切换时，操作系统要：

1. 保存当前线程/进程的寄存器、PC 等状态。
2. 恢复下一个线程/进程的状态。

### 协程

传统协程是协作式的：协程主动让出，比如遇到 await、yield 时才切换；不是像线程那样被时间片抢占。
线程是 OS 调度的执行流，协程是用户态调度的执行流。
协程不是替代线程，而是让线程更高效地被利用。线程负责并行和 CPU 调度，协程负责在等待 I/O 时把线程让出来干别的活。

协程的核心是“保存现场 + 恢复现场”。

- 遇到 `await`、`yield` 等挂起点，协程保存当前执行状态，让出执行权。
- 调度器去跑其他就绪协程。
- 等 I/O 就绪或条件满足，再恢复这个协程继续执行。

适合：

- **I/O 密集型高并发**：一个线程管理成千上万连接。
- 网络服务、爬虫、网关、API 聚合。
- UI 事件循环、游戏逻辑。
- 生成器、惰性计算、状态机。

不适合：

- **CPU 密集型**：单线程协程无法利用多核，算力不会变多。
- 大量阻塞式系统调用：一个阻塞可能卡住整个事件循环。
- 需要强隔离的场景：协程之间隔离弱，一个崩溃可能影响同线程其他协程。
