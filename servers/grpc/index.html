极简讲解

gRPC

一句话：让两台机器像「直接调用本地函数」一样互相说话的快车道。

① 先懂什么叫 RPC

RPC = Remote Procedure Call（远程过程调用）。你调一个函数，但函数在另一台机器上跑。

调用方 被调用方 返回结果

② gRPC 是什么

gRPC 是 Google 开源的 RPC 框架：帮你把「定义接口 → 打包数据 → 发送 → 解包 → 调用」全自动化。

③ 怎么工作（一次调用）

从写 proto 到拿到结果，分四步走完。

1

定义接口

写一个 .proto 文件，声明有哪些方法、参数和返回值。

2

生成桩代码

用工具一键生成客户端 Stub 和服务端 Stub（各语言版本）。

3

发起调用

客户端像调本地函数一样调，数据被 protobuf 压成二进制走 HTTP/2。

4

服务端返回

服务端执行真正逻辑，把结果原路压回，客户端自动解包拿到对象。

④ 两个关键零件

gRPC 又快又省，靠的是下面两样东西。

A

Protobuf

把数据压成二进制，比 JSON 小很多、解析快很多，还自带「字段叫什么」的合同。

B

HTTP/2

一条连接上并发多个请求，双向流，省连接、低延迟。

⑤ 不只是「一问一答」

gRPC 支持 4 种调用模式，比普通 HTTP 灵活。

⑥ 和 REST 有啥不一样

REST 更通用、人好读；gRPC 更快、更适合服务之间内部通话。

对比点REST + JSONgRPC + Protobuf
数据格式文本（JSON）二进制（小且快）
传输协议HTTP/1.1 为主HTTP/2 多路复用
接口合同靠文档约定.proto 强类型自动生成
调用模式基本一问一答4 种流式
浏览器直连天然支持需 gRPC-Web 网关
最适合对外 API / 前端服务间内部通话

⑦ 打个比方

gRPC 就像两家公司之间配了 同款对讲机 + 统一话术本： 话术本（.proto）规定好「问什么、答什么」，对讲机（HTTP/2）又快又能同时讲， 所以两边像 坐在同一间办公室喊话 一样自然——其实人还隔着几栋楼。

⑧ 记住一句话

gRPC = 自动化的远程函数调用：用 .proto 当合同，用 protobuf 压数据，用 HTTP/2 飞， 让跨语言、跨机器的调用又快又像本地函数。
