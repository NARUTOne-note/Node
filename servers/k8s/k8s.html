Kubernetes（K8s）是什么

你说「我要 3 个副本」，它负责找机器、启动、挂了重启 —— 一个自动照顾程序的「码头调度系统」

控制平面：集群的大脑

  • • 它自己不跑你的程序，只负责「安排」
  • • API Server：唯一出入口，所有请求都先找它
  • • Scheduler：挑一台合适、还装得下的机器
  • • Controller：盯着实际状态，缺了就补上
  • • etcd：唯一的账本，存着集群的「应该长什么样」

工作节点：真正干活的机器

  • • kubelet：驻场监工，替总部照看本机上的 Pod
  • • kube-proxy：把访问 Service 的流量导到具体 Pod
  • • 容器运行时：真正把容器启动起来的那只手
  • • 一台机器上可以跑很多个 Pod，按需分配
  • • 机器坏了，Pod 会被安排到别的机器上重开

必须记住的三个名字

  • • Pod：最小的运行单元，里面装 1 个或多个容器
  • • Deployment：你声明「我要 3 个副本」，它来维持
  • • Service：给一组随时会变的 Pod 一个固定门牌
  • • YAML：你用文件写下「我想要什么」，而不是「怎么做」
  • • 三者关系：Deployment 管 Pod，Service 找到 Pod

为什么大家都用它

  • • 声明式：说「我要什么」，系统自己去对齐
  • • 自愈：程序挂了自动重启，机器挂了自动搬家
  • • 滚动更新：新版一个个换，出问题可以回滚
  • • 弹性伸缩：忙时加副本，闲时减副本
  • • 你只做三件事：写 YAML → apply → 看状态

Docker 和 K8s 是什么关系？—— 上下游，不是竞品

Step 1 · 打包

Docker：把程序打进盒子

把程序连同依赖装进一个标准盒子（镜像）。
它管的是「一个容器」，在「一台机器」上跑。

→
Step 2 · 存放

镜像仓库 Registry

盒子统一存放的地方（Docker Hub / Harbor / 云厂商）。
你 push 上去，任何机器都能 pull 下来。

→
Step 3 · 调度

K8s：安排到整个车队

把盒子在几十上百台机器上跑起来，管副本、管故障、管扩容、管流量。
K8s 不负责打包，也不自己造盒子。

• 镜像通用：Docker 打出来的镜像 K8s 原样能跑 —— 都遵守 OCI 标准。Docker 内部用的就是 containerd，K8s 现在的默认运行时也是 containerd。

• 不是二选一：Docker 管「一个容器」，K8s 管「一堆容器」；Docker Desktop 自带的本地 K8s 就是两者一起用的典型。

• 一句话记住：Docker 是把货装进集装箱的装货工，K8s 是决定箱子放哪条船、哪个泊位的码头调度中心。
